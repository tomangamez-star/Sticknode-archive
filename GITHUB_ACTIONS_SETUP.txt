GITHUB ACTIONS — PYTHON INGEST + MINI RETRIEVER

The archive job still runs in GitHub Actions. Render remains the Telegram bot/search host.

Required GitHub repository secrets:
- TELEGRAM_TOKEN
- DATABASE_URL
- ARCHIVE_CHAT_ID
- SCRAPERAPI_KEY

How the fetch path works now:
  python_ingest/ingest.py
        -> python_retriever/retriever.py
        -> ScraperAPI standard API endpoint
        -> target response
        -> existing parser / SHA-256 / PostgreSQL / Telegram archive

The existing Chrome/undetected-chromedriver code is still present. It is now lazy and only starts if:
  INGEST_FETCH_PROVIDER=chrome

The GitHub workflow uses:
  INGEST_FETCH_PROVIDER=retriever
  RETRIEVER_PROVIDER=scraperapi

ScraperAPI key setup:
1. Create/sign in to a ScraperAPI account.
2. Copy the API key from the ScraperAPI dashboard.
3. GitHub repo -> Settings -> Secrets and variables -> Actions.
4. New repository secret.
5. Name: SCRAPERAPI_KEY
6. Value: paste the API key.
7. Save.

Then run:
  Actions -> Stick Nodes archive ingest -> Run workflow

detected and rejected instead of being archived as a real page/file.
